A mi compañero le sale otro modelo con default

Qué está pasando

Depende del tipo de cuenta, y cambió en v2.1.219

01Diagnóstico probable

default no es un modelo: es un valor especial que limpia cualquier anulación y vuelve al recomendado para tu tipo de cuenta. Y ahí está la trampa: «default» significa cosas distintas según quién pague.

02Compruébalo

› /status

Dentro de una sesión. Mira el modelo efectivo de esta sesión, que es el dato que zanja la discusión

$ claude --version

En la terminal. Mira 2.1.219 o posterior; por debajo, default resolvía a otra cosa

03Solución

  1. Mira la tabla y localiza vuestras cuentas: Max, Team Premium, Enterprise de pago por uso y API de Anthropic resuelven a Opus 5; Claude Platform on AWS, Amazon Bedrock y Agent Platform de Google, a Opus 5; Pro, Team Standard y plazas de suscripción Enterprise, a Sonnet 5; Microsoft Foundry, a Sonnet 4.5.
  2. Si queréis comparar de verdad, fijad el modelo explícitamente con --model en las dos máquinas en vez de confiar en default.
  3. Y comprobad la versión: antes de v2.1.219, default resolvía a Opus 4.8 en varias de esas filas. Si una máquina no está actualizada, no estáis comparando lo mismo.
Pasa si

/status muestra el mismo modelo en las dos máquinas, o sabéis nombrar por qué son distintos.

Aplica desde
2.1.219 para la resolución actual de `default`
Evidencia
Comprobación ejecutada. El comando de «Compruébalo» se lanzó contra Claude Code 2.1.229 los días 13 y 14 de agosto de 2026 y devolvió lo que dice esta página. Ejecutar la comprobación no es reproducir la avería: el arreglo sale de la fuente citada. Fuente: model-config.md. claude --version se ejecutó: 2.1.229, por encima del corte.
No aplica si
Vuestra organización fija un modelo por defecto desde settings gestionados. Entonces default resuelve a ese, no al de la tabla.
